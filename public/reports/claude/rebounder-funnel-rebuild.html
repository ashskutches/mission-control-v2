Why the blog is the lever

Two findings set the direction. First, 80.3% of commercial rebounder queries are answered by a blog post, not a page that sells — so the blog is where the funnel has to start. Second, our own click-through at positions 7–10 is a median 0.60% across 157 pages, where a healthy site earns 2–3%; that is the signature of ranking for questions our page isn't the answer to.

Page speed was ruled out early. Field data from real Chrome users: 15 of 15 top pages pass Core Web Vitals, zero failing, mobile LCP 1.3–1.5s. Worth knowing because a throttled Lighthouse score says the opposite and has previously sent this project down that road.

Found along the way

Twelve things already broken

None of these were caused by this work. Several are worth fixing whether or not the funnel ships.

  1. 01
    Three font clamps that could never workThe blog hero used clamp(1.5rem, 4.0714rem, 3rem). A clamp whose preferred value is a fixed length larger than its own maximum can only return the maximum — so all three were fixed sizes wearing a clamp, and the title never scaled on any screen. Fixed.
  2. 02
    Personalization path-matching has never fired oncelrb-personalization.js derives visitor context from paths like /blogs/senior and /blogs/knee. Your blog handles are news and mini-trampoline-workouts, so those strings never occur. The senior, knee and athlete contexts the system was built to detect are dead code against this store's URLs. OPEN
  3. 03
    The product page shows "0 reviews · 0.0 average"On your highest-traffic page, that reads as "nobody bought this." Meanwhile the blog CTAs cite a 5-star rating. OPEN
  4. 04
    A byte-identical duplicate productthe-best-fitness-trampoline has the same description, the same SEO title and the same meta description as the main rebounder. It is in the rebounders collection and unpublished to the storefront. OPEN
  5. 05
    The product page contradicts itself four waysWarranty (lifetime vs standard), assembly (~8 min vs "<20 mins"), shipping ("2–6 business days" and "2–6 Weeks"), and colours — the copy lists Black, which doesn't exist, and omits Pink and Purple, which do. I used the conservative version of each. OPEN
  6. 06
    The category page ranks 55.8 for its own name/collections/rebounders sits at position 55.8 for "rebounders" while the homepage (10.4) and the product page (13.9) outrank it. It's correctly titled and schema'd — it has no internal links. OPEN
  7. 07
    Two landing templates render identical outputpromo-landing and promo-landing-v3 both return 95,817 bytes with the same section id. Editing one expecting a difference won't produce one. OPEN
  8. 08
    66% of buying queries are split across your own URLs479 of 724 commercial queries are served by more than one page of yours — "best rebounder trampoline" across 53 URLs, "best rebounder for lymphatic drainage" across 36. OPEN
  9. 09
    Independent confirmation of that self-competitionSummed across the page dimension your impressions total 553,323 against a property total of 492,620. Google counts one impression per search event; the page dimension counts one per URL shown. That 12.3% excess is your pages appearing beside each other.

    "Compare Models" goes to the product pageOn the 257 workout articles, hardcoded inside lrb-workout-show.liquid — not to /pages/comparisons. OPEN
  11. 11
    The cart app leaks to the sale collectionRebuy Smart Cart's empty-cart message has a "Shop Now" button pointing at /collections/sale. App setting, not theme. OPEN

Corrections

Six things I got wrong

The one that nearly shipped a regression

I set the article measure to 68 characters, measured paragraph.getBoundingClientRect().width, got "76 characters, done" and moved on. But the paragraph box was 726px while the text was wrapping around a 450px floated image into about 40 characters — worse than the 1200px column it replaced. My check measured the box, not the lines. I only caught it from a screenshot.

The second measurement used Range.getClientRects() — actual rendered line rectangles — which is what I should have done first.

  1. 02
    Deployed a template before the section it configuresShopify silently strips settings it doesn't recognise. Because the old schema was still live, size_option_value and all six bridge settings were dropped — 200 response, no errors, plausible-looking file. Caught only by the stored byte count. Section before template from then on.
  2. 03
    Made the mobile header taller when the ask was desktopThe original was 50vw capped at 600px, so a 500px screen was already 250px. My flat 300px made narrow screens worse. Restored to the original curve.
  3. 04
    Overstated your own data as conversion evidenceI argued for a sales page partly on the advertorial page's 5.78% CTR. That page has no cart — so 5.78% is search click-through, not conversion. The honest position: the sales page is well-supported by infrastructure, not by measured conversion, because GA4 attributes $0 to every page.
  4. 05
    Said "all 785 articles" when it was 528The workout blog uses a different template with no article-content section at all, so the reading fix never reached its 257 articles.
  5. 06
    Three byte mismatches from editing copy mid-transcriptionI improved a setting's label or info text while typing it into the deploy call but not in the local file. Harmless, but it meant local and theme had drifted. The byte-size check caught all three; everything is now in sync.

Platform limits

Seven things the platform won't let us do

All verified against your store, not assumed. These are the reasons several things are built the way they are.

  • 01
    Liquid cannot read query parametersThere is no request.params. That is why lrb-personalization.js uses URLSearchParams, and why the context bridge has to be client-side. Its default copy is real HTML so crawlers and no-JS visitors still get something that stands alone.
  • 02
    Only one personalization embed per pageThis is the answer to abstracting the header and footer into two embeds. lrb-personalization.js has a global run-once guard, reads a single EMBED_ID from one global config, and mounts into one hardcoded element id. A second embed aborts itself. Two independent slots need the script reworked for multiple instances.
  • 03
    The bandit's reward can't reach an article CTAThe two-level UCB1 engine already exists and variations are first-class, with per-variation impressions, clicks and add-to-carts. But it scores on add-to-carts, and the impression list resets per page load — so a CTA seen on the blog can never be credited for a cart two pages later. Reward stays 0 and the bandit degenerates into the round-robin its own code comments warn about. Ranking on clicks is the fix.
  • 04
    templateSuffix lives on the record, not the themeSo a per-collection template can't be staged on an unpublished theme. Hence the handle-gate pattern now used in four sections: a comma-separated handle list, blank meaning "behave as before everywhere."
  • 05
    article.handle is prefixed with the blog handleIt returns news/the-cons-of-rebounding, not the slug alone — which put an unencoded slash in a query value until it was fixed.
  • 06
    Never put utm_* on an internal linkIt starts a fresh GA4 session and re-attributes the visit away from its real source. The context parameter is deliberately named lrbctx.
  • 07
    ?view= does work hereVerified: it renders a different product template on the same URL with the canonical unchanged and the full variant picker intact; a bogus value falls back to the default with a 200. That is the route to a page that converts in place, if the advertorial step is ever cut.
