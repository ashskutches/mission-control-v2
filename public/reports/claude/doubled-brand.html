The doubled brand

Five of the ten highest-traffic pages render a <title> containing the brand name twice, pushing every one of them past Google's truncation point. The cause is a single line of Liquid. Nothing has been changed — this is for your review.

Summary

  • One theme bug. A brand-suffix guard uses a literal substring match against shop.name (“Leaps and Rebounds”). Titles written with an ampersand — “Leaps & Rebounds” — fail the match, so the suffix is appended anyway and the brand appears twice.
  • Affected: 5 of the 10 top pages, including the main product page (13,616 impressions/28d) and /collections/sale. All five land at 84–88 characters against a ~60-character display limit.
  • The fix is one line and needs no copy changes. Correcting the guard takes all five titles from 84–88 down to 63–67 characters with the keywords intact.
  • Separately: 8 of 10 meta descriptions exceed ~160 characters and are being truncated. That one is per-page copy work, and it is your call, not a bug.
Finding 01 Defect Scope: theme-wide Effort: one line Risk: low, reversible

Brand name emitted twice in <title>

snippets/meta-tags.liquid builds the title and appends the shop name only when it isn't already present. The guard is the right idea; the comparison is too literal: 

<!-- snippets/meta-tags.liquid — as it currently stands -->
<title>
  {{ page_title }}
  {%- if current_tags %} &ndash; tagged "{{ current_tags | join: ', ' }}"{% endif -%}
  {%- if current_page != 1 %} &ndash; Page {{ current_page }}{% endif -%}
  {%- unless page_title contains shop.name %} &ndash; {{ shop.name }}{% endunless -%}
</title>

shop.name is “Leaps and Rebounds”, spelled out. So a hand-written SEO title ending in “Leaps & Rebounds” does not contain shop.name, the unless passes, and the suffix is added on top of a brand name that was already there. Titles that spell out “and” match, and are correctly left alone.

The argument does not depend on the CTR data

Even if the correlation is entirely coincidental, emitting the brand name twice in an 84–88 character title is a defect on its own terms: it wastes the visible portion of the title on repetition, and it is not what the SEO titles were written to say. Fix it because it is wrong, and treat any CTR improvement as a bonus rather than the justification.

Recommended change

Normalise the ampersand before the comparison. Two lines, no change to any page's copy, and it also protects any page not in this audit that uses the same shorthand. 

<!-- snippets/meta-tags.liquid -->
{%- assign title_norm = page_title | replace: '&', 'and' -%}
<title>
  {{ page_title }}
  {%- if current_tags %} &ndash; tagged "{{ current_tags | join: ', ' }}"{% endif -%}
  {%- if current_page != 1 %} &ndash; Page {{ current_page }}{% endif -%}
  - {%- unless page_title contains shop.name %} &ndash; {{ shop.name }}{% endunless -%}
  + {%- unless title_norm contains shop.name %} &ndash; {{ shop.name }}{% endunless -%}
</title>

"Leaps & Rebounds" normalises to "Leaps and Rebounds", matches shop.name, and the suffix is correctly suppressed. Only the comparison is normalised — the title still renders exactly as written, ampersand and all.

How I would sequence it

  1. Apply the two-line theme fix on a duplicate of the live theme

    Duplicate 163472212184, edit snippets/meta-tags.liquid, preview. Confirm the five titles render at 63–67 characters and that the five clean pages are unchanged.

  2. Check the blast radius beyond these ten pages

    The audit covered the ten highest-traffic URLs. Any page whose SEO title uses “Leaps & Rebounds” has the same defect — worth a crawl to count them before publishing, since the fix helps all of them at once.

  3. Publish, then leave it alone for 28 days

    Titles need re-crawling before anything moves. Compare CTR at matched position, per URL, against the 28 days prior. Do not read sitewide CTR — it moves for unrelated reasons.

  4. Only then consider rewriting copy

    Trimming to under 60 characters and reordering the descriptions are separate decisions. Doing them at the same time as the bug fix makes the result unattributable.

Cautions

Do not publish the existing dev theme

There is an unpublished theme, 163676356824, carrying an unrelated conversion-funnel rebuild. Publishing it to ship a title fix would release all of that too. Duplicate the live theme instead.

Change one variable at a time

These are revenue pages. The bug fix is attributable; a simultaneous rewrite of titles and descriptions is not. If CTR drops you want to know which change did it.

Rollback is a one-line revert

The change is confined to snippets/meta-tags.liquid. Reverting restores the previous behaviour exactly; no page data, redirect or SEO field is touched.

Expect a lag, and possible volatility

Google re-crawls and may test titles of its own, and can override a title it judges poor. Judge the change over 28 days, not days.
